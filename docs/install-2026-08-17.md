# The install, executed — INSTALL.md's prompt, 2026-08-17

*Unedited console. Every step of the prompt on [INSTALL.md](../INSTALL.md),
run in a clean environment on the maintainer's Mac before the page shipped.*

**H-7's law: executed before shipped, or labelled.** This is the execution, and
it is the only reason INSTALL.md does not carry a "not yet exercised" banner.

## What "clean" meant, exactly

- a fresh, empty `UV_TOOL_DIR` and `UV_TOOL_BIN_DIR`
- an empty working directory
- **`$HOME/.local/bin` removed from `PATH`**, so the maintainer's own installed
  `wring` could not answer for the one being installed. The first line of the
  transcript is the proof: `not on PATH — nothing is installed yet`.

Two things this run does NOT test, said plainly: the repositories are cloned
from local checkouts rather than over the network — it exercises the STEPS, not
GitHub's availability, and the URLs on the page are the real ones — and no
coding agent was in the loop. A human ran the prompt's instructions in order.
Whether a given agent follows them correctly is not something this can settle.

## What running it FOUND, which reading it did not

Three defects, all in the prompt, all fixed before it shipped:

1. **The Python prerequisite check was wrong and would have stopped a PM for
   no reason.** The draft asked for Python ≥ 3.11. This machine's `python3` is
   **3.9.6** and the install works perfectly, because `uv` fetches and manages
   its own Python. The check is now git and uv, and the transcript records the
   3.9.6 to show why.

2. **The visible moment had no referent — the reviewer's HIGH, confirmed by
   execution.** The draft ran `wring verify` inside the cloned `wringer` repo.
   That repo's gates are `ruff check …` and `pytest -q`, and a tool install
   does not put a project's *development* tools on the gate's PATH, so the very
   first thing a PM would have seen was `/bin/sh: ruff: command not found`. The
   board over that run then said *"nobody has written down what the work is
   for"*, because the repository has no approved spec — so there was no card to
   look at either.

   **`--with ruff --with pytest` does not fix it**, and that was the second
   attempt: `uv tool install --with` installs into the tool's own environment,
   not onto the PATH the gate's shell searches. It failed identically.

3. **`uv` lives in `$HOME/.local/bin` on this machine, beside `wring`.** Two
   earlier casts put uv's directory on PATH and thereby re-admitted the exact
   binary the run existed to exclude, so the transcript's opening line
   contradicted its own claim of cleanliness. Fixed by symlinking `uv` alone.

**The step that failed twice was CUT rather than fixed a third time.** Setting
up another project's development environment is an engineer's job, and this page
is not for that. What survives is a tiny project the agent builds from three
files, whose one check really runs and needs nothing installed — and which is a
better demonstration anyway, because the PM watches a requirement go from
refused to proved.

## The moment itself

Look at the two boards in step 4. Between them, three characters of code
changed. The first says **1 holding up the handover** and *"the check that will
decide it is written and failing right now"*. The second says **DONE — AND
PROVED** and **"It was red first."**

That is the entire argument of the project, on a repository that did not exist
ninety seconds earlier, on the reader's own machine.
