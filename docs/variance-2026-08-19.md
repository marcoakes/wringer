# What four identical drafting calls disagree about (2026-08-19)

Four `wring spec --send` calls, **the same PRD**, the same model, the same
request — measured because SPEC_PMPLAN_V0 needed to know what a product manager
is actually consenting to when they approve a drafted plan.

The four replies are captured byte for byte at
`tests/replies/2026-08-19-arcade-run{1..4}-drafter-reply.json`. Nothing here is
reconstructed; every number below is read from those files.

**The input really was identical.** `prompt_tokens` is **2206 on all four
runs**. So every difference in the table is sampling variance, not a different
question asked four ways.

| run | questions | required | criteria | tasks | buried decisions | out tokens |
|---|---|---|---|---|---|---|
| 1 | 2 | 2 | 9 | 3 | **4** | 4813 |
| 2 | 2 | 2 | 10 | 3 | 0 | 5193 |
| 3 | 2 | 2 | 12 | 4 | **3** | 5100 |
| 4 | 3 | 3 | 11 | 3 | **3** | 5364 |

Total spend for the measurement: 8824 prompt tokens, 20470 completion tokens.

## 1. The question cap holds — and it is a prompt, not a guard

Required questions came back **2, 2, 2, 3**. The rule *"AT MOST THREE
QUESTIONS"* lives in `render_request`'s prose (`spec.py:661`) and **nothing at
parse time enforces it**. It held here. It also held on 2026-08-17 that a
binding must not repeat a declared gate, right up until the drafter proposed
`pytest -q` as both in the same reply.

Prompts are not guards. SPEC_PMPLAN_V0 ruling 3 makes this one a guard.

## 2. What the PM is asked depends on the roll

Every run asked `what-counts-as-played`. After that they diverge:

- run 1 — `clearing-history`
- run 2 — `per-browser-memory`
- run 3 — `retired-game-in-history`
- run 4 — `memory-scope`, `clearing-history`

**Run 2 asked whether history is per-browser. Run 1 decided it silently** and
wrote the decision into a criterion's test guidance:

> *"Decision taken without asking: this is per-browser only — there are no
> accounts, so the list does not follow a person to another device or browser,
> and that is acceptable."*
> — run 1, criterion `survives-tab-close`

Same PRD. One PM is asked; another is not, and finds out only if they read the
`guidance` field of an acceptance criterion. **What a person consents to
depends on a die they cannot see.**

## 3. The drafter writes assumptions into a field that is not for them — and labels them differently every time

The request tells the drafter to *"write your decision into the criterion it
affects"* (`spec.py:671`) and gives it **no field to put a decision in**. So it
invents one, in prose, inside `guidance`.

**Ten criteria across three of the four runs carry such a decision** — and each
run labels them its own way:

| run | phrasing it chose | criteria |
|---|---|---|
| 1 | `Decision taken without asking:` | 4 |
| 2 | *(none)* | 0 |
| 3 | `Decision taken unless overruled:` | 3 |
| 4 | `Decision taken unless the memory-scope question says otherwise:` | 3 |

This is the finding that cost SPEC_PMPLAN_V0 a rewrite. Its first draft matched
run 1's literal sentence, which finds **4 of the 10** decisions actually
present and reports runs 3 and 4 as entirely clean. The stable substring is
`decision taken`.

**And that is still only a heuristic.** The phrasing varied three ways in four
rolls; a fourth phrasing walks past any of them, and no structural check can
replace it, because nothing distinguishes decision prose from check prose
except its meaning. The detector's **silence is not evidence** that a draft
took no silent decisions. It is written down here so that nobody later reads a
clean run as a proof of one.

**Run 2 is the negative control, and it came free.** It is the run that *asked*
the memory-scope question instead of deciding it, and it is the run with zero
markers. The detector fires on exactly the runs that decided silently and stays
quiet on the one that asked — a red-and-green pair from real captured bytes
rather than a mutation.

## 4. What this measurement does not say

It does not say four runs are enough to characterise the variance — they are
not, and the numbers above are a sample of four, not a distribution. It does
not say run 2 took no silent decisions; it says run 2 wrote no sentence
labelling one. And it does not say the criteria counts (9, 10, 12, 11) reflect
different amounts of work — nobody built all four.

What it does say is narrow and enough: **on one unchanged PRD, the set of
decisions a product manager is invited to make is not stable, and the decisions
they are not invited to make are recorded where they will not read them.**
