# Same job, both workers, and no winner

*`wring bench` runs the same repair through every worker your repo declares,
one at a time, under identical conditions, and writes one comparison bundle.
**It measures. It does not crown** — and the recording below is what that
sentence costs, and why it is worth paying.*

This is [specs/SPEC_BENCH_V0.md](specs/SPEC_BENCH_V0.md) end to end. Everything below
is **real captured output** from a scratch repository, produced by
`scripts/demo.sh` — regenerated by running it again, never edited by hand.

---

## The recording

![wring bench: same job, both workers, and no winner](bench.svg)

Two contenders, one job. Both converge in two iterations. Both take half a
second. Every column Wringer measured says they did **equally well** — and on
those columns, they did.

Then the last two commands, which is where the demo turns:

```console
$ git -C .wringer/worktrees/<bench>-careful diff --stat HEAD
 calc.py | 2 +-

$ git -C .wringer/worktrees/<bench>-hasty diff --stat HEAD
 test_calc.py | 2 +-
```

One contender fixed the function. The other rewrote the failing assertion
into a tautology. **A benchmark that ranked these rows would have crowned the
liar**, because rewriting a test is faster and cheaper than fixing code, and
every measurable in the table rewards it.

That is not a hypothetical. It is
[specs/SPEC_VACUITY_V0.md](specs/SPEC_VACUITY_V0.md) §5a's stated blind spot, and with
the contender's `HEAD` unmoved the neutered tree even records a `proven`
vacuity verdict. An auto-ranked bench would systematically reward
reward-hacking, in the product built to catch it. So there is no winner, no
score, and **no ordering field in any schema of this format** — the rows come
out in declared order, the limits print underneath them, and the reader ranks
with the diffs in front of them.

## What is in the demo repo

`multiply` is wrong and a committed test says so — the gate is **red at
HEAD**, because a benchmark of repair needs something to repair. A green
baseline is refused (exit 1) rather than measured, since N workers would each
"converge" in zero iterations against work that was already done.

The two contenders are shell scripts, not agents. That is not a shortcut
around a vendor binary: it is what makes the recording reproducible by
anyone, with no credential and no install.

```yaml
bench:
  contender_wall_clock: 120
  contenders:
    - id: careful
      worker: "sh ./careful.sh"    # fixes the function
    - id: hasty
      worker: "sh ./hasty.sh"      # rewrites the assertion
```

A real comparison names agents instead, and the `agent:` sugar takes an id
from `wring start`'s table — never a command, because the only file that may
put a command in Wringer's mouth is `.wringer.yaml`:

```yaml
    - id: claude
      agent: claude-code
    - id: gemini
      agent: gemini
```

## What makes the rows comparable

Four things, each checked rather than assumed:

| | |
|---|---|
| **a red baseline** | verified for real before anything else runs; green exits 1 and names its evidence |
| **one common tree** | every contender worktree's sha is read back and checked against the baseline's; a commit landing mid-creation is exit 2 naming both shas |
| **identical ceilings** | every contender's loop is handed the *same* `contender_wall_clock`, never a remainder — nobody is measured under conditions their predecessor set |
| **isolation that outlives the bench** | each contender runs in its own worktree at a bench-scoped path, so a second bench cannot delete the first one's evidence |

Contenders may vary **the worker and nothing else**. No per-contender gates,
budgets or environments: a contender key that could loosen a ceiling would be
the flags-only-tighten rule broken inside a file.

Serial, on purpose. Parallel contenders on one machine contend for CPU, IO
and the network, and wall-clock is a primary column — concurrency would
corrupt the numbers the command exists to report.

## Two kinds of number, kept apart

**Measured by Wringer**, always present: wall-clock, iterations, worker
invocations, gate seconds, the changed-file list, and `head_moved` — whether
the worker moved its worktree's `HEAD`. The harness never writes git history,
but a worker is somebody else's agent and may commit, and every tree-anchored
verdict in that row is then relative to a tree the agent moved.

**Reported by the agent**, present only when reported: token counts and the
agent's own cost, recorded verbatim as its claim and marked unverified. An
agent that reports nothing gets an **absent** field, rendered `—`, never `0`
— a zero would be a number Wringer made up about somebody else's spending.

There is no price table. Pricing would be a third module of vendor strings
that is wrong the week after it is written, so cost is what the agent said it
was, in the agent's own currency, or it is absent.

## Exit codes

| | |
|---|---|
| `0` | the comparison exists — **not** that anybody converged |
| `1` | nothing to measure: no required gate fails at the baseline |
| `2` | config or environment: an invalid `bench:` section, an absent agent binary at preflight, a worktree/setup/sha failure |
| `3` | refused — mid-merge or mid-rebase |
| `4` | interrupted |

`wring run` exits 1 when its loop does not converge and bench deliberately
does not follow it. `run` *executes* a repair, so non-repair is its failure;
bench *observes*, so the observation completing is its success. A contender
that failed to converge is a **result**, recorded in its row. An instrument
that exited non-zero after successfully measuring a failure would be
reporting its own health with the patient's chart. Read outcomes with
`--json`.

## The evidence, and reclaiming the disk

The bench bundle is `.wringer/benches/<bench_id>/` — an append-only
`prev_hash`-chained `bench.jsonl` verified by the same chain function `wring
audit` uses, a schema-versioned `manifest.json`, a `summary.md`, and
`digests.json` written last over everything. Loop and verify bundles are
referenced by path and never nested.

Those loop bundles live **inside the kept worktrees**, which is why the
worktrees are kept: a bench that removed them would be a bench that removed
its own evidence. The summary prints the lines that reclaim the disk, and
runs none of them:

```console
git worktree remove .wringer/worktrees/<bench>-baseline
git worktree remove .wringer/worktrees/<bench>-careful
git worktree remove .wringer/worktrees/<bench>-hasty
```

## What a bench does not tell you

The three limits print with every run, ride in the manifest, and repeat in
`--json`, because a benchmark is the artifact most likely to be read as a
larger claim than it is:

1. **One run per contender.** Agents are stochastic; a difference within
   noise is noise.
2. **Usage and cost are the agent's own report, unverified.** Absent means
   unreported, never zero.
3. **A green gate proves the gates went green, not that the fix is honest** —
   read the diffs before believing any row.

The third one is the recording above, and it is the whole design.
