# R1 — a refused delivery, driven for real, with the record beside it

*The capture `specs/SPEC_REFUSAL_V0.md` §9 asks of slice R1. The house does not
claim unfilmed work, so this file exists before the slice is called landed.
Everything below is pasted from a real run on 2026-08-17; nothing here is
hand-written to look like output.*

## The repository

A scratch git repository with one gate and a `deliver:` section, verified
once so a bundle exists. `origin` is declared and does not exist, which is
what makes the refusal fire — the remote's default branch cannot be
determined, so delivery refuses rather than guess at which branch it must
avoid.

```yaml
version: 1
gates:
  - id: tests
    run: python3 -c "import calc; assert calc.add(1,2)==3"
deliver:
  branch: "wringer/{run}"
  remote: origin
```

## The refusal

```
$ wring deliver
wring deliver: the remote's default branch could not be determined, so Wringer
cannot be sure it is avoiding it. Make 'origin' answer, then record its
default locally:
  git fetch origin
  git remote set-head origin -a
Setting 'deliver.base' does not clear this, and neither does the branch name:
the default is resolved whatever 'base' says, because 'base' names the branch
the merge request targets and has never meant 'skip the check'
$ echo $?
3
```

## The console is unchanged, and that was measured rather than believed

The same command was run twice against the same repository: once with the
pre-R1 code (`0779165~1`, checked out into a worktree and put on
`PYTHONPATH`), once with R1. The two outputs were diffed.

```
$ diff before.txt after.txt
$ echo $?
0
```

Byte-identical, and both exited **3**. R1 adds a write; it changes nothing a
person sees and nothing a script branches on.

## What the run also shows, which is the part worth checking

**`.wringer/deliveries/` does not exist.** It is absent before the refusal
and absent after it:

```
$ ls .wringer/deliveries
ls: .wringer/deliveries: No such file or directory
```

This is the review's finding made visible. The spec as drafted said the
record went into "a delivery directory allocated for the attempt", and there
is no such directory at any of the 23 refusals — every `raise Refused(` is
inside `deliver.plan()`, and `Bundle.create` is not reached until `plan()`
has returned. Had the record been written under `.wringer/deliveries/`
anyway, `attest.latest_anchor` would have taken it as the newest anchor and
`wring attest` would have refused — *"not a Wringer bundle — there is no
manifest.json in it"* — silently, until the next successful delivery.

**One record per attempt.** The second run wrote a second directory:

```
$ ls .wringer/refusals/
20260817-041517-ec9a
20260817-041532-c55a
```

Nothing prunes them, counts them, or aggregates them, and no command
enumerates the refusals root — §8's non-goal 9 forbids a refusal history, and
this is a record, not a history.

**A config error is not a refusal and writes nothing.** Run before the
`deliver:` section existed, the same command exited 2 with
*"no 'deliver:' section in .wringer.yaml"* and left no `.wringer/refusals/`
at all. That is a `DeliverError`, not a `Refused`, and the choke point that
records is the one that catches `Refused`. The distinction is in the record
set rather than in a sentence about it.
