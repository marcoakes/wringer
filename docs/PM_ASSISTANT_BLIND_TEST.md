# PM assistant entry point: next-test protocol

Status: protocol, **not a result**. Use a new frozen candidate and new evidence
directory. Do not edit the alpha.3 run or promote its salvage into a pass.

## Declare the condition before starting

Record the exact Wringer commit/version, client/product/version, OS, runtime,
ACP adapters, model configuration, credential state without values, and the
operator's prior familiarity. Name the entry page and task. An implementation
agent is not an independent stranger.

Choose one condition and do not switch labels mid-run:

- **Cooperative-local laboratory PM evaluation:** the operator has provisioned a
  real contained profile and explicitly accepted the documented same-user trust
  limitation. This may test usability and workflow; it cannot pass protected mode.
- **Protected outsider PM blind test:** begin only after a measured OS/controller
  and genuine human-confirmation boundary is available. Today this condition is
  blocked; the correct product behavior is a clear refusal.

Pre-provisioned is not clean-machine. Record tools, disk availability, existing
credentials and configuration actually measured. Keep installation effort
separate from steady-state PM attention. Never include secret values or private
operator URLs in the public transcript.

## Freeze and hand over

Give the PM only [ASSISTANT_START.md](../ASSISTANT_START.md), the frozen product,
their task and the declared provisioning. No coaching from this protocol during
the blind phase. No product or document edits mid-test.

The assistant may handle mechanics the product documents. Human observations
and consequential approvals come from the actual person. A route the product
prints is part of the product. An undocumented fix, invented flag, remembered
path or edited state is hand repair: capture the entire stop and end the blind
verdict there. Further exploration is separately labelled salvage with every
repair recorded verbatim.

## Observe the complete loop

1. **Connect:** use only the printed route. Inspect an existing client entry
   before changing it; no whole-file configuration overwrite, key re-entry or
   global permission weakening. Record the exact tools discovered and limits.
2. **Request:** preserve the PM's original words. Expose assumptions and missing
   answers. Inert proposal creation must not start a hidden paid planner.
3. **Approve:** the person sees the exact repository/source, requirements,
   allowed work, session/time ceilings and expiry before approval. Record every
   routine versus consequential permission interruption.
4. **Execute:** the assistant starts that approved job once. Red-first checks,
   contained worker and independent judge remain distinct. A provider rejection
   stops without repeated automatic attempts. ACP completion is not called a
   successful build.
5. **Disconnect:** close the client connection at a recorded point, reopen it,
   find the same job and inspect status. Compare operation IDs and reservations;
   reconnect must not silently buy another call. Label an owner-process kill as
   a separate interruption drill, with exact before/after effect state.
6. **Correct:** preserve the PM's correction in their own words. Offer only
   currently eligible actions. A changed scope or spent grant requires a real
   new decision, not a silent larger allowance or another root.
7. **Judge:** show the actual candidate successfully before offering a human
   verdict. Preserve a negative note as faithfully as a positive one. An unseen
   application or failed display is a stop, not approval by assistant summary.
8. **Handover:** show the exact change and destination. Refuse once to establish
   no publication occurred. A later deliberate yes is separate from execution
   approval. Sent branch, hosted request, merge and deployment are distinct.
9. **Audit:** clone the actual delivery remote into a fresh directory and follow
   the delivery's own literal audit command from the place it names. Compare
   assistant, board, certificate, summary and MR facts and the human note.
10. **Finish:** run the printed optional breakage test only with its separately
    bounded runtime authority; record unavailable as unavailable. Read final
    status/doctor and both usage lanes. Nothing becomes £0 because it is absent.

## Evidence and verdict

Retain every command and response, the original request/questions/notes, complete
stops, setup pages, operation/source/candidate identities, approval moments,
display receipt, delivery bundle, audit transcript and any breakage-test record.
Redact secrets before publication while retaining a protected original where
appropriate. Record the start/end wall clock, active PM attention, pauses,
undocumented interventions and all hesitations.

Report coding-app usage separately from Wringer-managed role sessions/tokens
and billed cost. Missing values remain unknown. No savings percentage may be
derived from unknown bills or compared across unmatched conditions.

The result is PASS, FAIL at the first blind stop requiring hand repair, or
INCOMPLETE with the exact remaining boundary. A contained agent failing to
converge is a fact about that bounded attempt. Do not replace an honest failure
with a scripted success and call it the same test.

Publish the frozen result and limitations even when it fails. A short demo may
summarize that real run, but must label editing/time compression and link the
complete sanitized evidence. It must not claim five-minute execution unless
five minutes was actually measured.
