## 2026-09-28 — distribution, migration and channels

- One bounded POSIX ustar verifier is shared by archive generation, extraction
  measurements and the installed product. Extensions, device/hard links, parent
  conflicts and undeclared aliases refuse. Same-origin checksums are integrity
  checks; CI attestations remain separately identified provenance.
- Versioned installation is separate from application state. Migration means
  original-semantic readers plus a preserved prior binary, with no rewrite of
  active jobs. Live owners and derived unfinished reservations hold switching.
  Rollback requires all prior schema bytes to remain supported, conservatively
  refusing a target missing any currently installed sibling.
- npm omits symlinks in real tarballs. Platform packages therefore have their
  own exact regular-file inventory; the original archive inventory is retained
  under an explicit provenance filename. The thin launcher owns alias dispatch,
  checks exact version/binary digest and never downloads at execution time.
- No npm namespace is selected for publication. Actual local package tests use
  a private fixture scope. Production generation requires an explicit fresh
  namespace observation, and publication remains behind a separate environment.
- Action release selection comes from its own ref and package version, with
  source mode explicit. It never uses a consumer repository tag. The verifier's
  exit code survives reporting failures; partial selection stays visibly partial.
- Runtime image workflow builds each OCI architecture natively and measures
  package/OS inputs without agents. Docker image construction is build machinery,
  not a new delegation runtime or a claim that Apple/gVisor isolation passed.
- Repository licence is Apache-2.0. An intermediate private npm fixture incorrectly
  declared MIT; the retained red test caught this metadata error and the generator
  now matches LICENSE. Those earlier package bytes are not the final candidate.

- Lost verification outcomes now bind a v2 reservation to a predetermined output
  path and a sealed final completion sibling. Explicit recovery reads it without
  executing checks or renewing limits. Legacy v1 reservations lack this binding
  and remain uncertain. Lost displays remain missing rather than inferred.
- Actual npm tarballs are parsed and checked before any registry command. Native
  packages must match their original clean-source archive inventory; draft
  sidecars and npm measurement reports bind the selected archive, not just version.
- Current Homebrew documentation specifies named tapped formulae. The native CI
  procedure therefore creates an explicitly owned disposable tap, installs/tests
  by qualified name, and removes only its own tap/formula. Brew is absent here.
- No old evidence or corpus was archived/deleted. Current entry guides were
  rebuilt; historical evidence/client report bodies remain beneath dated current
  candidate sections. README retains the original banner and authorship credit.
- alpha20 is an unused visible prerelease candidate as of2026-09-28. Package and
  workspace metadata were advanced locally; no tag or publication was created.
  Authenticated private-draft inspection remains blocked by existing401 credentials.
